# Evidence

These files are **generated by parsing the training logs, trace files and run states
directly** — no number in this repository's prose was transcribed by hand from a screen.
If a claim and a file here disagree, the file is right.

| File | What it holds | How it was produced |
|---|---|---|
| `milestones.json` | Every `CREDIT_MILESTONE` record from all 12 training runs: 92 records, each with the credible-glide rates, longest/mean glide, entry speed, discounted and undiscounted return, per-term termination counts and the checkpoint hash | parsing the `*-training.log` files |
| `gates.json` | Every gate report on disk, grouped by stage: 15 per-seed reports plus one aggregate | reading `*/gate-*.json` |
| `coast-down.json` | Per-checkpoint glide physics: entry-speed distribution, fitted deceleration per glide, exit-speed distribution, exit reasons, budget-used, and the derived 2.0 s requirements | reading `records/full-trace-*.json` |
| `checkpoints.json` | SHA256 and size of every shipped checkpoint, plus the pinned-source hashes recorded by the runs that produced them | hashing the shipped files and reading `state.json` |

## Reading `coast-down.json`

The `coast_down` array inside the raw traces is the **credible glide segment** of each
first episode: `entry_speed` is the first credible speed, `exit_speed` the last,
`duration_s` the segment length, `accel` the fitted slope over that segment, and
`exit_reason` the *episode's* termination terms — which may fire after the glide itself
ended. Glides whose `exit_speed` is at the 0.10–0.135 m/s floor ended on speed; glides that
exit well above it ended by losing balance.

`derived_2s_requirement_mps` is `0.10 + 2.0 · |mean deceleration|`, and
`derived_shortfall_at_mean_entry_mps` is that requirement minus the mean entry speed. Both
are computed from the trace, so they move together with it.

## What is deliberately absent

* **The 876 MB of raw training artifacts** (nested per-run logs, event files, intermediate
  checkpoints, per-stage source snapshots). The screening series they contain is distilled
  into `milestones.json`; the full artifacts stay in the working tree.
* **`course.json`**, the live coordinator state, is included under `records/` as a
  snapshot, not as this directory — it names paths in the live working tree.
